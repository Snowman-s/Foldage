# Foldage 言語仕様

## 第 1 章 はじめに

### 1.1 本書の構成

本書は難解プログラミング言語 Foldage を定める。処理系は本書に従う。

- 第 2 章 字句構造: ソーステキストを行と字句に分ける規則
- 第 3 章 構文: 字句の並びとインデントから 1 本の木を組み立てる規則
- 第 4 章 木: プログラムであり実行時の状態でもある、ラベル付き順序木
- 第 5 章 ルール: どのノードがルールとして働くか、照合と置換の組み立て
- 第 6 章 実行: 書き換えの進め方、停止と結果
- 第 7 章 正規形: 木を 1 通りのソースとして書き出す規則
- 第 8 章 例（参考）
- 付録 A 文法のまとめ

### 1.2 表記

**規範と参考**: 本文は規範である。「**注**」「**例**」で始まる段落と第 8 章は参考であり、規範の内容を補足するだけで、新たな決まりを加えない。

**用語**: 用語は、それを定義する箇所で太字にする。第 2 章・第 3 章でソーステキストに課す「〜でなければならない」「〜してはならない」に反するソーステキストは、**構文エラー**（§3.6）である。

**参照**: 「§5.3」は本書の 5.3 節を指す。

**文法**: 生成規則を次の記法で書く。非終端記号には英語の名前を付け、本文の用語に対応するものは、その用語を定義する箇所に括弧で示す。

| 記法 | 意味 |
|---|---|
| `A ::= …` | 非終端記号 A の定義 |
| `x \| y` | x または y |
| `{x}` | x の 0 回以上の繰り返し |
| `[x]` | x の省略可能な出現 |
| `'c'` | 文字 c そのもの |
| `〈…〉` | 文章で説明する文字の集合 |

**文字**: U+0020 を「空白」、U+0009 を「タブ」、U+000A を「LF」、U+000D を「CR」と呼ぶ。

**木の説明用表記**: 説明では木を S 式で書くことがある。葉 t は `t`、ラベル l と子 c₁, …, cₙ（n ≥ 1）を持つノードは `(l c₁ … cₙ)` と書く。これはソースの構文ではない。ソースから木への対応は `s: add ?m ?n` ⟹ `(s (add ?m ?n))` のように書く。

### 1.3 概要（参考）

この節は参考である。

プログラムは 1 本の木である。実行するとその木が葉から根に向かって少しずつ書き換えられ、「畳まれて」いく。最後に根が単一のアトム（シンボルまたは文字列）になれば、それが出力になる。

書き換えのルールも木の一部である。根が単一のアトムになった時点で、木にルールは 1 本も残っていない（§6.6）。したがって、プログラムは計算の最後に自分のルールを畳み込んで消さなければ終われない。**自己改変は言語の飾りではなく、終了するための必須条件である。** これが、設計方針「必要性のある難解さのみを入れる」に対するこの言語の答えである。

- **記述**: インデント（空白 2 個で 1 段）と行内ネスト記号 `:` で木を書く。行内の部分木を書く糖衣構文として `()` も使える（第 2 章・第 3 章）
- **値**: シンボルと文字列はどちらもアトムだが、互いに別のものである。シンボルは名前で区別されるだけで、文字列は中身を持つ（第 4 章）
- **変数**: 単独の `?x` は任意の部分木に一致し、子を持つノードのラベル位置に置いた `?f` はラベルだけに一致する。列変数 `?..xs` は兄弟の並びに一致し、左から最短で取る。`??x` はルールを生成するルールのためのエスケープである（第 5 章）
- **戦略**: 最左最内。1 ステップに 1 箇所だけ書き換え、各位置では近いスコープのルールから試す（第 6 章）
- **組込み**: 文字列 2 つの連結 `++` だけを持つ。これは、根より外側のスコープに置かれたルール群として定義する（§6.4）
- **入出力**: 入力はない。出力は、最後に残ったアトム 1 つである（§6.6、§6.7）

## 第 2 章 字句構造

### 2.1 ソーステキスト

**ソーステキスト**は、UTF-8 で符号化された Unicode スカラー値の列である。UTF-8 として正しくないバイト列はソーステキストではなく、処理系はこれを誤りとして報告する。

ソーステキストの先頭が U+FEFF（BOM）であれば、その 1 文字を取り除いてから以降の処理を行う。先頭以外にある U+FEFF は取り除かない（置ける位置は §2.4 による）。

### 2.2 行

ソーステキストを**行終端子**で区切った各部分を**行**とする。行終端子は CR LF の並び、または（CR に続かない）LF である。CR の直後に LF が続かない場合、その CR は普通の文字である。ソーステキストの末尾が行終端子で終わっても、その後ろに空の行は作らない。

先頭から数えて n 番目（1 始まり）の行の**行番号**を n とする。無視される行（§2.3）も数に含める。行番号は、行の順序（§3.4）と構文エラーの報告（§3.6）に用いる。

### 2.3 インデント

各行について、行頭から続く空白の個数を k とし、その空白を除いた残りを**行本体**とする。

行本体が空の行と、行本体が `#` で始まる行（コメントだけの行）を**無視される行**とする。これらは字句（§2.5）を 1 つも含まない。無視される行は、以降の処理（第 3 章）では存在しないものとして扱う。

無視されない行では、k は偶数でなければならない。このとき、k / 2 をその行の**深さ**とする。

### 2.4 空白・タブ・コメント

行本体の中で、空白は字句の区切りである。

タブ・CR・U+FEFF は、文字列リテラル（§2.7）の中とコメントの中にだけ置ける。それ以外の位置（行頭の空白の直後を含む）にこれらを置いてはならない。

**注**: CR と U+FEFF は目に見えないうえ、シンボルの名前に入ると正規形（第 7 章）を読み戻したときに同じ木に戻らない。行末に書き出した CR は直後の LF と合わせて行終端子になり、ソースの先頭に書き出した U+FEFF は BOM として取り除かれるからである。

**コメント**（`comment`）は、字句の先頭となるべき位置に現れた `#` から行末までである。コメントは無視される。字句の途中に現れた `#` はコメントを始めず、その字句の一部になる。

**例**: `a b#c` は 2 つの字句 `a` と `b#c` からなる。`a b #c` は字句 `a` と `b` に、コメント `#c` が続く。

### 2.5 字句

行本体を左から読み、次の規則を繰り返して**字句**（`lexeme`）の列に分ける。

1. 空白なら読み飛ばす
2. `#` なら、そこから行末までをコメントとして捨てる
3. `(` なら、**開き括弧**（`open-paren`）の字句とする
4. `)` なら、**閉じ括弧**（`close-paren`）の字句とする。直後に `:` があれば、それも含めて 1 つの字句とする
5. `"` なら、文字列リテラル（§2.7）を読む。直後に `:` があれば、それも含めて 1 つの**文字列字句**（`string-lexeme`）とする
6. それ以外なら、**名前字句**（`name-lexeme`、§2.6）を読む。名前字句は、空白・タブ・CR・U+FEFF・`(`・`)` のいずれでもない文字の、最長の並びである

```
lexeme        ::= open-paren | close-paren | token-lexeme
token-lexeme  ::= string-lexeme | name-lexeme
open-paren    ::= '('
close-paren   ::= ')' [':']
string-lexeme ::= string-literal [':']
name-lexeme   ::= name-char {name-char}
name-char     ::= 〈any character except space, tab, CR, U+FEFF, '(' and ')'〉
comment       ::= '#' {〈any character〉}
```

字句のうち、文字列字句と名前字句を**トークン字句**（`token-lexeme`）と呼ぶ。トークン字句はトークン（§4.1）を 1 つ表す。

閉じ括弧とトークン字句は、末尾に `:` を伴うかどうかの情報（**コロン印**）を持つ。開き括弧はコロン印を持たない。

**注**: `(` と `)` はそれ自体で区切りになる。したがって `f(x)` は `f (x)` と、`f (a)b` は `f (a) b` と同じ字句列になる。

### 2.6 名前字句

名前字句 w を次のように解釈する。

1. w が `:` で終わるなら、コロン印を付け、末尾の `:` を 1 個だけ取り除く。残りを**本体**（`body`）とする。w が `:` で終わらないなら、w 全体を本体とし、コロン印は付けない
2. 本体は次をすべて満たさなければならない
   - 空でない
   - `"` を含まない
   - `:` で始まらない
   - `:` で終わらない
3. 本体の先頭から続く `?` の個数を n とし、その後ろの部分を r とする
   - n = 0 なら、本体を名前とする**シンボル**である
   - n ≥ 1 で r が `..` で始まるなら、r から `..` を除いた部分を名前とする、レベル n の**列変数**である。名前は空であってはならない
   - n ≥ 1 でそれ以外なら、r を名前とする、レベル n の**変数**である。名前は空であってはならない

```
name-lexeme  ::= body [':']
body         ::= symbol-name | variable | seq-variable
variable     ::= '?' {'?'} name
seq-variable ::= '?' {'?'} '..' name
```

`?` の並びは最長に取る。`?` の並びの直後に `..` がある場合は、`seq-variable` として読む。

**注**: 本体が `:` で始まらないことは、`)` の直後の `:` を一通りに読むために必要である（§2.8）。本体が `:` で終わらないことは、正規形（第 7 章）を読み戻したときに同じ木になるために必要である。シンボル名をエスケープする手段は設けない。シンボルは名前で区別できれば十分で、任意の文字を含める必要がないからである。

**例**: `a:b` は名前 `a:b` のシンボルである。`a:` はコロン印付きのシンボル `a` である。`?..xs:` はコロン印付きの、レベル 1 の列変数 `xs` である。`?`、`?..`、`:`、`:a`、`a::` はいずれも構文エラーである。

### 2.7 文字列リテラル

```
string-literal ::= '"' {string-char} '"'
string-char    ::= 〈any character except '"' and '\'〉 | escape
escape         ::= '\"' | '\\' | '\n'
```

文字列リテラル（`string-literal`）は同じ行のうちに閉じなければならない。`\` の後には `"`・`\`・`n` のいずれかが続かなければならない。

文字列リテラルの**値**は、文字列文字（`string-char`）を順に並べた文字列である。ただし、エスケープ列（`escape`）`\"`・`\\`・`\n` はそれぞれ `"`・`\`・LF の 1 文字を表す。

文字列字句の直後（閉じる `"`、またはそれに続く `:` の直後）は、行末・空白・`)` のいずれかでなければならない。

**例**: `"a"b`、`"a"(b)`、`"a""b"` は構文エラーである。`f (a)"s"` は `f a "s"` と同じである。

### 2.8 行内ネスト記号

トークン字句と閉じ括弧のコロン印を**行内ネスト記号** `:` と呼ぶ。その意味は §3.2 で定める。

`)` の直後の `:` は、常に閉じ括弧のコロン印として読む。本体は `:` で始まらない（§2.6）ので、この読み方は一通りに決まる。

**例**: `f (a b):c d` は `f (a b): c d` と同じである。`s :` の `:` は単独の名前字句になり、本体が空なので構文エラーである。

## 第 3 章 構文

### 3.1 行の構文

無視されない各行（§2.3）の字句列は、次の生成規則の `line` に従わなければならない。

```
line     ::= sequence
sequence ::= item {item}
item     ::= token-lexeme | open-paren sequence close-paren
```

括弧は同じ行のうちで対応が取れていなければならない。

`item` に従う字句列を**項目**、`sequence` に従う字句列を**並び**と呼ぶ。項目のうち、括弧で囲んだものを**括弧項目**と呼ぶ。項目のコロン印は、トークン字句ならそのトークン字句の、括弧項目なら閉じ括弧のコロン印とする。

**注**: 括弧は行をまたげない。行をまたぐ入れ子はインデントで書く。空の `()` は `item` に従わないので構文エラーである。

### 3.2 並びの解釈

項目 I の**値** v(I) と、ノードの**コロン末尾**（最後の子が `:` で付いたかどうかを表す真偽値）を次のように定める。

- トークン字句 I の値は、そのトークンを持つ葉である。コロン末尾は偽とする
- 括弧項目 `( S )` の値は、並び S を解釈したノードである。コロン末尾は、S を解釈したときのコロン末尾とする

並び I₁ … Iₙ（n ≥ 1）を次のように解釈し、ノード 1 つとコロン末尾を得る。

1. Iₙ がコロン印を持ってはならない
2. I₁, …, Iₙ のうち、コロン印を持つ最初の項目を Iₖ とする
   - Iₖ がなく n = 1 なら、結果は v(I₁) とする。コロン末尾は I₁ のものとする
   - Iₖ がなく n ≥ 2 なら、結果は、I₁ のトークンをラベルとし、v(I₂), …, v(Iₙ) を子とするノードとする。コロン末尾は偽とする
   - Iₖ があるなら、残りの並び Iₖ₊₁ … Iₙ を解釈したノードを N とする。結果は、I₁ のトークンをラベルとし、v(I₂), …, v(Iₖ), N を子とするノードとする。コロン末尾は真とする
3. 結果が子を持つノードになる場合（2 の 2 つ目と 3 つ目）、I₁ は括弧項目であってはならない

行の字句列を並びとして解釈した結果を、その行の**行ノード**とする。

**注**: 「行のその位置から右側全体を最後の子とする」のが `:` である。`:` は右結合で、括弧の中の `:` の範囲はその括弧の終わりまでである。要素が 1 つだけの括弧は、その要素自身になる。

**例**:

| ソース | 木 |
|---|---|
| `s: add ?m ?n` | `(s (add ?m ?n))` |
| `s: s: s z` | `(s (s (s z)))` |
| `a b: c d` | `(a b (c d))` |
| `add (s: s z) (s z)` | `(add (s (s z)) (s z))` |
| `a (b c): d e` | `(a (b c) (d e))` |
| `(a)` | `a` |
| `s: (a b)` | `(s (a b))`（`s: a b` と同じ） |
| `(a b) c` | 構文エラー（括弧項目がラベルの位置にある） |

### 3.3 ラベルの制約

子を持つノードのラベルは、シンボルまたは変数（レベルを問わない）でなければならない。文字列と列変数は、子を持つノードのラベルになってはならない。この制約は、§3.2 で作るすべてのノードと、§3.4 で子ブロックを付け終えた行ノードに適用する。

**注**: ラベルは木の形を名付けるもので、文字列は計算される値である。両者の役割を分けるため、文字列はラベルにしない。列変数は並びを表すので、1 つのラベルにならない。変数をラベルに許すのは、パターンのラベル位置に置く変数（§5.3）や、それを生成するルール（`?f ??x` など）を書けるようにするためである。

### 3.4 子ブロック

無視されない行を、行番号の順に L₁, …, Lₘ とする。dᵢ を Lᵢ の深さとする。次が成り立たなければならない。

1. d₁ = 0
2. 各 i ≥ 2 について dᵢ ≤ dᵢ₋₁ + 1

dᵢ ≥ 1 である行 Lᵢ の**親行**は、i より前にある行のうち、深さが dᵢ − 1 である最後の行とする。ある行を親行とする行の並びを、その行の**子ブロック**と呼ぶ。

各行の行ノードに、子ブロックの各行のノード（その行自身の子ブロックを付け終えたもの）を、行番号の順に子として付け加える。子ブロックの子は、行内に書いた子の後に続く。

子ブロックを持つ行の行ノードは、コロン末尾が偽でなければならない。

**注**: コロン末尾の行に子ブロックを付けると、子ブロックが外側と内側のどちらのノードに付くのかが曖昧になる。子の位置にある括弧の中の `:` は `)` で範囲が閉じるので、コロン末尾にはならない。たとえば `a (b: c)` には子ブロックを付けられる。一方で、行全体を 1 つの括弧で囲んだ `(s: z)` は `s: z` と同じ（§3.2）なので、コロン末尾は真になり、子ブロックを付けられない。

### 3.5 プログラム

ソーステキストには無視されない行が 1 つ以上なければならず、そのうち深さ 0 の行はちょうど 1 つでなければならない。

深さ 0 の行の行ノードに子ブロックを付け終えたものを、そのソーステキストが表す**プログラム**とする。プログラムは整形された木（§4.6）である。

### 3.6 構文エラー

次のいずれかに該当するソーステキストは**構文エラー**である。処理系は構文エラーを報告し、プログラムを実行してはならない。報告には、誤りを含む行の行番号を含めることが望ましい。

| 誤り | 定める節 |
|---|---|
| 無視されない行の行頭の空白が奇数個 | §2.3 |
| 文字列リテラルとコメントの外にタブ・CR・U+FEFF がある | §2.4 |
| 名前字句の本体が空、`"` を含む、`:` で始まる、または `:` で終わる | §2.6 |
| 変数・列変数の名前が空 | §2.6 |
| 文字列リテラルが同じ行で閉じていない | §2.7 |
| 文字列リテラル中の `\` に `"`・`\`・`n` 以外が続く | §2.7 |
| 文字列字句の直後が行末・空白・`)` のいずれでもない | §2.7 |
| 括弧の対応が同じ行で取れていない、または `()` が空 | §3.1 |
| 並びの最後の項目がコロン印を持つ | §3.2 |
| 子を持つノードのラベルの位置に括弧項目がある | §3.2 |
| 子を持つノードのラベルが文字列または列変数 | §3.3 |
| 先頭の行が字下げされている、または親行より 2 段以上深い行がある | §3.4 |
| コロン末尾の行が子ブロックを持つ | §3.4 |
| 無視されない行がない、または深さ 0 の行が 2 つ以上ある | §3.5 |

## 第 4 章 木

### 4.1 トークン

**トークン**は次の 4 種類のいずれかである。

| 種類 | 構成要素 | ソースでの書き方 |
|---|---|---|
| **シンボル** | 名前 | `z`、`main`、`->`、`++` |
| **文字列** | 文字の列（空でもよい） | `"hello"`、`""` |
| **変数** | レベル n ≥ 1 と名前 | `?x`（n = 1）、`??x`（n = 2） |
| **列変数** | レベル n ≥ 1 と名前 | `?..xs`（n = 1）、`??..xs`（n = 2） |

2 つのトークンは、種類が同じで構成要素がすべて等しいときに限り等しい。したがって、シンボル `abc` と文字列 `"abc"` は異なり、変数 `?x` と列変数 `?..x` も異なる。

シンボルは名前で区別されるだけで、内部の構造を持たない。分解することも連結することもできない。文字列は中身を持つ値であり、組込みの連結（§6.4）の対象になる。

変数と列変数も、ほかのトークンと同じく木に置かれる。変数として解釈されるのは、ルールのパターンと置換に使われるとき（第 5 章）だけである。

### 4.2 ノード

**ノード**は、**ラベル**と呼ぶトークン 1 つと、**子**と呼ぶノードの有限列の組である。子が 0 個のノードを**葉**と呼ぶ。トークン t をラベルとする葉を、単に「葉 t」または t と書く。

**注**: 葉とトークンを同一視するので、アトム `greet` と、ラベルが `greet` で子が 0 個のノードは同じものである。

### 4.3 アトム

ラベルがシンボルまたは文字列である葉を**アトム**と呼ぶ。ラベルが変数または列変数である葉は、アトムではない。

### 4.4 位置

**位置**は、0 以上の整数の有限列である。木 T の位置 p にある部分木 T|p を次のように定める。

- 空列 ε について、T|ε = T（**根**）
- T|p の i 番目（0 始まり）の子があるとき、T|p·i をその子とする

T|p が定まる位置 p を T の位置とする。p が q の真の接頭辞であるとき、p は q の**祖先**である。p·i の祖先のうち最も近いもの p を**親**と呼ぶ。

T[p ← S] は、T の位置 p にある部分木を S に置き換えた木を表す。

T の位置の**帰りがけ順**は、各位置について「子の位置を左から順に（各子の部分木の帰りがけ順で）並べ、最後にその位置自身を置く」ことで得られる順序である。

### 4.5 等しさ

2 つのノードは、ラベルが等しく、子の数が等しく、対応する子どうしがそれぞれ等しいときに限り等しい。

**注**: 子の数も比べるので、葉 `rev` と子を持つノード `(rev "a")` は等しくない。

### 4.6 整形された木

子を持つすべてのノードのラベルがシンボルまたは変数である木を、**整形された木**と呼ぶ。

プログラムは整形された木である（§3.3）。整形された木に 1 ステップ（§6.5）を適用した結果も、整形された木である（§5.5、§6.4）。

## 第 5 章 ルール

### 5.1 ルールノード

次をすべて満たすノード N を**ルールノード**、または単に**ルール**と呼ぶ。

1. N のラベルはシンボル `->` である
2. N の子はちょうど 2 つである。1 つ目を N の**パターン**、2 つ目を N の**置換**と呼ぶ
3. 置換に現れるレベル 1 の変数と、レベル 1 の列変数は、すべてパターンにも現れる

3 で「現れる」とは、ラベルとしてであれ葉としてであれ、その部分木のいずれかのノードのラベルがそのトークンであることをいう。置換の中にある入れ子の `->` の内部も数える。

1 と 2 を満たすが 3 を満たさないノードはルールではなく、ただのデータである。

あるノードがルールかどうかは、そのときの木の上で判定する。書き換えによってルールがデータに、データがルールに変わりうる。

**注**: 3 を満たさないルールは、置換を組み立てられない（§5.5）ので、適用されることがない。そのようなノードはデータとして扱い、その内部も書き換えの位置にする（§6.2）。置換の中のレベル 2 以上の変数は 3 の対象にならない。そのため、ルールを生成するルールは置換に `??x` を書く（§5.5）。

**例**: `-> greet ?x` はルールではない。`-> (mkid ?f) (-> (?f ??x) ??x)` はルールである。`-> (mkid ?f) (-> (?f ?x) ?x)` はルールではない。

### 5.2 束縛

**束縛** σ は、名前からノードへの有限写像 σ₁ と、名前からノードの有限列への有限写像 σ₂ の組である。レベル 1 の変数 `?x` には σ₁(x)、レベル 1 の列変数 `?..xs` には σ₂(xs) が対応する。以下では σ₁(x) を σ(?x)、σ₂(xs) を σ(?..xs) と書く。

**レベル下げ** ↓t を、トークン t について次のように定める。

- t がレベル n ≥ 2 の変数なら、同じ名前のレベル n − 1 の変数
- t がレベル n ≥ 2 の列変数なら、同じ名前のレベル n − 1 の列変数
- それ以外なら t 自身

### 5.3 照合

パターン P が束縛 σ のもとでノード T に**一致する**ことを、次のように定める。ここで、σ の定義域は P に現れるレベル 1 の変数と列変数の名前にちょうど等しいものとする。

**ノードの一致**: P が T に一致するかどうかを、P の形によって次のように定める。

1. P がレベル 1 の変数 `?x` の葉なら、σ(?x) = T のとき一致する
2. P のラベルがレベル 1 の変数 `?x` で、P が子を持つなら、σ(?x) が「T のラベルの葉」に等しく、かつ P の子の列が T の子の列に一致するとき一致する
3. P のラベルがレベル 1 の列変数なら、一致しない。これはパターン全体が `?..xs` の場合にだけ起こる
4. それ以外なら、T のラベルが ↓(P のラベル) に等しく、かつ P の子の列が T の子の列に一致するとき一致する

**子の列の一致**: パターンの子の列 P₁, …, Pₘ が対象の子の列 T₁, …, Tₖ に一致するのは、T₁, …, Tₖ を連続する m 個の区間 S₁, …, Sₘ（空でもよい）に分けて、各 i について次が成り立つようにできるときである。

- Pᵢ がレベル 1 の列変数 `?..xs` の葉なら、σ(?..xs) = Sᵢ
- それ以外なら、Sᵢ はちょうど 1 つのノード Tⱼ からなり、Pᵢ が Tⱼ に一致する

**注**: σ は写像なので、同じ変数がパターンに 2 回以上現れれば、それらには等しい値が対応する（**非線形マッチ**）。列変数なら等しい並びが対応する。これにより、組込みなしで 2 つの木が等しいかどうかを判定できる。

**注**: 2 の条件から、ラベル位置の変数は、対象のラベルだけを「そのラベルの葉」として束縛する。そのため、同じ変数が葉の位置とラベル位置の両方に現れた場合、ラベル `s` と葉 `s` は同じ値として比べられる。また、T が葉なら「T のラベルの葉」は T 自身なので、子がすべて列変数のパターン `?f ?..xs` は、アトム `"abc"` にも一致する（`?f` は `"abc"` に束縛される）。

**注**: 4 により、パターン中のレベル 2 以上の変数は束縛を行わず、レベルが 1 つ低い同名の変数にだけ一致する。たとえばパターン中の `??x` はデータの `?x` に一致する。

### 5.4 照合の選択

P が T に一致する束縛は複数ありうる。その場合は、次の順序で最小のものを選ぶ。

P に現れるレベル 1 の列変数を、P の**行きがけ順**（各ノードを、その子より先に、子を左から順に）で最初に現れる順に `?..xs₁`, …, `?..xsₐ` とする。束縛 σ に長さの組（|σ(?..xs₁)|, …, |σ(?..xsₐ)|）を対応させ、この組の辞書式順序で最小の束縛を選ぶ。

列変数の長さがすべて決まれば、各区間の分け方も決まるので、最小の束縛はただ 1 つである。これを P と T の**照合結果** match(P, T) とする。P が T に一致する束縛がなければ、match(P, T) は定まらない。

**注**: 1 つの子の列に列変数が 1 個だけなら、その長さは子の数から一意に決まる。複数あれば、左の列変数ほど短く取る（**最短一致**）。

**例**: `f ?..a ?..b` を `f 1 2` に当てると、`?..a` は空列、`?..b` は `1 2` になる。`f ?..a x ?..b` を `f 1 x 2 x 3` に当てると、`?..a` は `1`、`?..b` は `2 x 3` になる（最初の `x` で区切られる）。`f ?..a ?x ?x` を `f 1 2 2` に当てると、`?..a` は `1`、`?x` は `2` になる。

### 5.5 置換の組み立て

置換 R と束縛 σ から、**組み立て** inst(R, σ) を次のように定める。inst は部分関数であり、定まらない場合がある。

**ノードの組み立て** inst(R, σ):

1. R がレベル 1 の変数 `?x` の葉なら、σ(?x)
2. R のラベルがレベル 1 の変数 `?x` で、R が子を持つなら、σ(?x) が「ラベルがシンボルまたは変数である葉」のときに限り、そのラベルをラベルとし、inst\*(R の子の列, σ) を子とするノード。σ(?x) がそれ以外（文字列の葉、列変数の葉、子を持つノード）なら定まらない
3. R のラベルがレベル 1 の列変数なら、定まらない
4. それ以外なら、↓(R のラベル) をラベルとし、inst\*(R の子の列, σ) を子とするノード

いずれの場合も、必要な σ の値がない場合は定まらない。

**子の列の組み立て** inst\*(R₁, …, Rₘ, σ) は、各 i について次の列を順に連結したものである。

- Rᵢ がレベル 1 の列変数 `?..xs` の葉なら、列 σ(?..xs)
- それ以外なら、1 要素の列 inst(Rᵢ, σ)

いずれかの inst(Rᵢ, σ) が定まらなければ、inst\* も定まらない。

**注**: 3 から、置換全体が列変数 `?..xs` であるルールは適用されない。根は 1 つのノードなので、並びに置き換えられないからである。2 は、子を持つノードのラベルはシンボルか変数に限る（§3.3）ことから来る。

**注**: 4 により、置換の中のレベル 2 以上の変数は、組み立てのたびに `?` が 1 つ消費される。置換中の `??x` は、生成された木の中で `?x` になる。

**例**: `-> (mkid ?f) (-> (?f ??x) ??x)` を `mkid id` に適用すると、`(-> (id ?x) ?x)` が組み立てられる。

### 5.6 ルールの適用

ルール ρ のパターンを P、置換を R とする。ノード T について σ = match(P, T) が定まり、かつ inst(R, σ) が定まるとき、ρ は T に**適用できる**といい、その**結果**を inst(R, σ) とする。それ以外の場合、ρ は T に適用できない。

**注**: inst(R, σ) が定まらないときに、σ 以外の一致する束縛を試すことはしない。

## 第 6 章 実行

### 6.1 実行の状態

プログラムの**実行**は、整形された木の列 T₀, T₁, T₂, … である。T₀ はプログラム（§3.5）で、各 Tᵢ₊₁ は Tᵢ に 1 ステップ（§6.5）を適用した結果である。

### 6.2 書き換え位置

木 T の位置 p について、p のどの祖先にもルールノードがないとき、p を**書き換え位置**と呼ぶ。

**注**: ルールの内部は書き換えられない（**不透明**である）。ただし、ルールノードそのものの位置は書き換え位置である。そのため、ルールのノード全体をメタルール `-> (-> ?p ?r) …` の対象にできる。また、ルールの中身は評価されないので、ルールは評価を遅らせた式（quote）としても使える。

### 6.3 スコープ

木 T の位置 q について、q の**スコープ** Sc(q) を、T|q の子のうちルールノードであるものを左から並べた列とする。

書き換え位置 p で試す**ルールの列** Rules(p) は、次の列をこの順に連結したものである。

1. T|p がルールノードでなければ Sc(p)。ルールノードなら空列
2. p の祖先を p に近い順に q₁, …, qⱼ（qⱼ = ε）として、Sc(q₁), …, Sc(qⱼ)
3. 外側スコープのルール（§6.4）

**注**: ルールが働く範囲は、そのルールの親ノードを根とする部分木である。その範囲には親自身も含む。含めないと、根を畳むルールが書けないからである。近いスコープのルールほど先に試し、同じスコープの中では左のルールを先に試す。

**注**: ルールは自分自身のノードにも、自分を含む親ノードにも適用されうる。ルールノードの位置 p では、そのルール自身を含む親のスコープから試す。T|p の子（パターンと置換）は、それ自体がルールノードであっても p では試さない。

### 6.4 外側スコープと組込みの連結

根よりさらに外側に、木には現れないスコープが 1 つあるものとする。これを**外側スコープ**と呼ぶ。外側スコープには、任意の文字列 a, b について次のルールが置かれている。

```
-> (++ "a" "b") "ab"
```

ここで `"a"`・`"b"` は a・b を値とする文字列の葉、`"ab"` は a と b をこの順に連結した文字列の葉を表す。

すなわち、ノード T が次をすべて満たすとき、外側スコープのルールが T に適用でき、その結果は T の 2 つの子の値をこの順に連結した文字列の葉である。

1. T のラベルはシンボル `++` である
2. T の子はちょうど 2 つである
3. 2 つの子はどちらも文字列の葉である

これ以外の T には、外側スコープのどのルールも適用できない。

外側スコープのルールは木の中にないので、照合の対象にならず、書き換えられることもない。`++` は予約されたシンボルではない。外側スコープにルールを持つという点を除けば、普通のシンボルである。

**注**: 純粋な書き換えでは、ソースに字面で書かれたアトムしか作れない。計算した結果を文字列として出力するには、最低限これが要る。このルール群は無限個あるが、どれも変数を含まない普通のルールである。処理系は列挙せず、連結の計算で代用する（λ計算の δ 規則と同じ扱い）。

**注**: 次の性質は、§6.3 から導かれる。

- 優先度が最も低い: 外側スコープはどの位置でも最後に試される
- 利用者のルールで上書きできる: より近いスコープのルールが先に試される
- 終了条件と矛盾しない: 外側スコープのルールは木の外にあるので、畳んで消す必要がない

**例**: 子が 2 つでない `++` や、子に文字列の葉以外（シンボル、子を持つノード）を含む `++` は、外側スコープでは畳まれない。

### 6.5 ステップ

木 T について、次を満たす書き換え位置 p を、帰りがけ順（§4.4）で最初のものとして選ぶ。

- Rules(p) のいずれかのルールが T|p に適用できる

そのような p があるとき、Rules(p) のうち T|p に適用できる最初のルールを ρ とし、その結果を S とする。T の**ステップ**の結果は T[p ← S] である。

そのような p がないとき、T は**停止状態**であり、ステップはない。

**注**: 戦略は**最左最内**である。1 ステップにつき 1 箇所だけを書き換える。最内を採るのは、折りたたみが葉から根へ向かう操作だからである。最外にすると、根が先に畳まれ、中身が未計算のまま残る。

**注**: ルールの判定（§5.1）も Rules(p) も、毎ステップそのときの木の上で行う。あるステップで書き換えられたルールは、次のステップから書き換え後の形で働く。

### 6.6 停止と結果

実行が停止状態 Tₙ に達したとき、実行は**停止**する。

- Tₙ がアトムなら、実行は**正常終了**する。処理系は、Tₙ がシンボルならその名前を、文字列ならその値（引用符を付けない中身）を出力する。出力は UTF-8 で符号化し、末尾に改行を加えない
- Tₙ がアトムでないなら、実行は**折りたたみ失敗**である。処理系は失敗を報告する。報告には Tₙ を正規形（第 7 章）で含めることが望ましい

停止状態に達しない実行は、終わらない。

**注**: T がアトムなら T は停止状態である。書き換え位置は根だけで、アトムには子がないので Sc(ε) は空であり、外側スコープのルールは子を 2 つ持つノードにしか適用できないからである。また、アトムは子を持たないので、ルールノードを含まない。すなわち、正常終了した時点で木にはルールが 1 本も残っていない。これが、プログラムは最後に自分のルールを畳み込んで消さなければ終われない（§1.3）ことの根拠である。

**注**: 根がルールノードであるとき、Rules(ε) は外側スコープのルールだけからなる。

### 6.7 入力と資源の上限

プログラムは入力を受け取らない。必要なデータは、初期の木に書いておく。

処理系は、ステップ数などの資源に上限を設け、上限に達したら実行を打ち切ってよい。その場合、処理系は打ち切ったことを報告しなければならず、正常終了として出力してはならない。打ち切りは折りたたみ失敗とは区別して報告する。

**注**: 処理系のオプションと終了コードは、言語の一部ではない。README を参照のこと。

## 第 7 章 正規形

正規形は、1 つの木に対して表示の仕方を 1 通りに決めたソーステキストである。処理系が木を表示するとき（折りたたみ失敗の報告やトレースなど）は、正規形を用いる。

### 7.1 トークンの字面

トークン t の**字面** text(t) を次のように定める。

| t | text(t) |
|---|---|
| 名前 s のシンボル | s |
| 値 s の文字列 | `"`、s の各文字を書き換えたもの、`"` の連結。s の各文字は、`"` を `\"` に、`\` を `\\` に、LF を `\n` に書き換え、それ以外の文字はそのまま書く |
| レベル n、名前 s の変数 | `?` を n 個並べたものに s を続けたもの |
| レベル n、名前 s の列変数 | `?` を n 個並べたものに `..` と s を続けたもの |

### 7.2 1 行で書けるノード

**1 行で書けるノード**を次のように帰納的に定める。

- 葉は 1 行で書ける
- 子 c₁, …, cₘ（m ≥ 1）を持つノードは、c₁, …, cₘ₋₁ がすべて葉で、cₘ が 1 行で書けるとき、1 行で書ける

1 行で書けるノード N の**単行形** line(N) を、語の列を空白 1 個で区切って連結したものとする。語の列は次のように定める。

- N が葉なら、text(N のラベル) だけからなる列
- N が子 c₁, …, cₘ を持つなら、text(N のラベル)、text(c₁ のラベル)、…、text(cₘ₋₁ のラベル) に続けて、
  - cₘ が葉なら text(cₘ のラベル)
  - cₘ が葉でないなら、それまでの最後の語の末尾に `:` を付け、line(cₘ) の語の列を続ける

### 7.3 書き出し

ノード N を深さ d で書き出した文字列 nf(N, d) を次のように定める。

- N が 1 行で書けるなら、空白 2d 個、line(N)、LF をこの順に連結したもの
- そうでないなら、N の子 c₁, …, cₘ のうち、先頭から続く葉の個数を j とする（j < m である）。空白 2d 個、text(N のラベル)、各 i ≤ j について空白 1 個と text(cᵢ のラベル)、LF をこの順に連結し、それに nf(cⱼ₊₁, d + 1), …, nf(cₘ, d + 1) を続けたもの

木 T の**正規形**は nf(T, 0) である。

**注**: 正規形は括弧・コメント・空の行を含まない。括弧は入力を書きやすくするための糖衣構文で、木には跡を残さないからである。

### 7.4 性質

整形された木 T に現れる各トークン t について、text(t) を第 2 章に従って読むとコロン印のないトークン字句 1 つになり、それが t を表すとする。このとき、nf(T, 0) を第 2 章・第 3 章に従って読み込んだプログラムは T に等しい。

**注**: 文字列は常にこの条件を満たす。シンボル・変数・列変数はすべてソーステキストのトークン字句に由来し（組込みの連結が作るのは文字列だけである）、そのトークン字句がこの条件を満たす。したがって、実行中の各ステップの木を正規形で表示すると、それはそのまま実行可能なソーステキストになる。ソースが少しずつ畳まれていく様子を、ソースのまま見せられる。

**例**: 次のソーステキストの正規形は `show: s z` である。

```
show
  s
    z
```

`show: add (s: s z) (s z)` の正規形は次のとおり。

```
show
  add
    s: s z
    s z
```

## 第 8 章 例（参考）

この章は参考である。各例のステップごとの遷移は[動作原理（図解）](how-it-works.html#stepper)の「サンプルを 1 ステップずつ」で見られる。

### 8.1 足し算の結果を棒の本数で出力する

```
main
  ->
    add z ?n
    ?n
  ->
    add
      s ?m
      ?n
    s: add ?m ?n
  ->
    show z
    ""
  ->
    show: s ?n
    ++ "|": show ?n
  ->
    main ?..rules ?r    # ルール群（自分自身を含む）ごと main を畳む
    ?r
  show
    add
      s: s z
      s z
```

最内戦略なので、計算は次の順に進む。

1. `add` が畳まれて `s: s: s z` になる
2. `show` が `++ "|": ...` の入れ子に展開される
3. 内側から `++` が連結されて `"|||"` になる
4. 最後に根の `main` が自分のルールごと畳まれる

出力は `|||`。

### 8.2 メタ書き換え

```
# step 0
main
  -> greet hello
  ->
    -> greet hello
    -> greet goodbye
  ->
    main ?..rules ?r
    ?r
  greet

# step 1: 2 本目のルールが 1 本目のルールを書き換えた
main
  -> greet goodbye
  ->
    -> greet hello
    -> greet goodbye
  ->
    main ?..rules ?r
    ?r
  greet

# step 2: 書き換えられたルールで greet が畳まれた
main
  -> greet goodbye
  ->
    -> greet hello
    -> greet goodbye
  ->
    main ?..rules ?r
    ?r
  goodbye

# step 3: 根が畳まれ、単一のアトムになった（出力）
goodbye
```

帰りがけ順では、1 本目のルールの位置が `greet` より先に来る。そのため、ルールが書き換えられてから `greet` が評価される。

### 8.3 ルールを生成するルール

```
main
  ->
    mkid ?f
    ->
      ?f ??x
      ??x
  ->
    main ?..rules ?r
    ?r
  mkid id
  id foo
```

`mkid id` が新しいルール `-> (id ?x) ?x` になり、そのルールが `id foo` を `foo` に畳む。最後に根が畳まれ、出力は `foo`。

### 8.4 文字列の並びを逆順にする

```
main
  ->
    rev ?c ?..rest
    ++
      rev ?..rest
      ?c
  -> rev ""
  ->
    main ?..rules ?r
    ?r
  rev "a" "b" "c"
```

`rev "a" "b" "c"` が `++ (++ (++ "" "c") "b") "a"` の形に展開され、内側から連結されて文字列 `"cba"` になり、`cba` が出力される。`rev` はシンボルなので、子に `rev` を含む `++` は畳まれない。

## 付録 A 文法のまとめ

この付録は第 2 章・第 3 章の生成規則を再掲する。生成規則だけでは表せない制約（インデント、名前字句の本体の制約、コロン印、ラベルの制約など）は各節による。

### A.1 字句文法（行本体）

```
lexeme         ::= open-paren | close-paren | token-lexeme
token-lexeme   ::= string-lexeme | name-lexeme
open-paren     ::= '('
close-paren    ::= ')' [':']
string-lexeme  ::= string-literal [':']
string-literal ::= '"' {string-char} '"'
string-char    ::= 〈any character except '"' and '\'〉 | escape
escape         ::= '\"' | '\\' | '\n'
name-lexeme    ::= name-char {name-char}
name-char      ::= 〈any character except space, tab, CR, U+FEFF, '(' and ')'〉
comment        ::= '#' {〈any character〉}
```

### A.2 名前字句

```
name-lexeme  ::= body [':']
body         ::= symbol-name | variable | seq-variable
variable     ::= '?' {'?'} name
seq-variable ::= '?' {'?'} '..' name
```

### A.3 行の文法

```
line     ::= sequence
sequence ::= item {item}
item     ::= token-lexeme | open-paren sequence close-paren
```
